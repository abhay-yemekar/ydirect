# Contributing

Thank you for helping improve yDirect's public product record.

## What is open to contribution

- documentation corrections and clearer explanations;
- accessible wording and formatting improvements;
- translations proposed for future review;
- safe, synthetic examples and use cases;
- reproducible product feedback and feature requests;
- broken public links and media accessibility issues.

## What is not in this repository

The extension, backend, infrastructure, tests, release packages, and private operational material are not open source and are not accepted as code contributions here.

## Before opening an issue

1. Search existing issues.
2. Remove personal, account, workspace, and snippet information.
3. Confirm the issue concerns a public document or a reproducible product behavior.
4. Use the security process for vulnerabilities or privacy incidents.

## Pull requests

1. Keep each pull request focused on one public-documentation or media concern.
2. Explain the problem and why the change improves accuracy or usability.
3. Use synthetic content only.
4. Preserve the product name as `yDirect`.
5. Do not add dependencies, executables, extension packages, source-code reconstructions, generated archives, tracking pixels, or external scripts.
6. Check Markdown links and image alt text.
7. Confirm that you have the right to contribute any media and agree that accepted contributions are licensed under the repository's CC BY 4.0 content license.

Acceptance is not guaranteed. Product positioning, security-sensitive detail, roadmap scope, brand use, and legal wording remain owner decisions.
