# yDirect public roadmap

This roadmap communicates product direction, not guaranteed dates. Priorities may change after user feedback, Chrome platform changes, security review, legal review, or operational learning.

## Shipped — foundation and public launch

- [x] Manifest V3 identity and permanent Chrome Web Store item ID
- [x] Account sign-in, local-first library, folders, search, and one-click copy
- [x] JSON, passphrase-encrypted JSON, and Excel portability
- [x] Optional cloud backup with latest and previous recovery points
- [x] Verified-account workspace roles and selective folder/snippet sharing
- [x] Public privacy, terms, support, uninstall, and changelog pages
- [x] Native side-panel migration and broad page-compatibility verification in `1.3.2`
- [x] Returning-user startup, worker authentication, workspace conflict, sharing, and compact-UI improvements in `1.3.3`
- [x] Chrome Web Store approval and public publishing through `1.3.3`
- [x] Current Store screenshots, promotional tiles, demo media, and public product documentation

## Now — adoption and confidence

- [ ] Triage post-launch feedback and remove onboarding friction
- [ ] Improve shortcut discovery and keyboard-first navigation
- [ ] Make backup health and recovery limits even easier to understand
- [ ] Expand safe, fake-data product walkthroughs around search, backup, and sharing
- [ ] Publish a verified compatibility matrix for common Chrome environments

## Next — usability and accessibility

- [ ] Guided first-run experience with optional sample snippets
- [ ] Accessibility review against current WCAG guidance
- [ ] Search improvements for larger libraries
- [ ] Additional import/export formats driven by real user needs
- [ ] More granular workspace membership controls

## Later — collaboration depth

- [ ] Optional contribution permission separate from view access
- [ ] Manager-visible resource activity history
- [ ] Notifications for member contributions and important workspace changes
- [ ] Recovery window for manager-deleted contributions
- [ ] Small-team governance features that remain easy to understand

## Exploring

- Browser support beyond Chrome where platform APIs and policy requirements align
- Faster library navigation for high-volume snippet collections
- Templates or starter packs that never expose real user data
- Community-led use-case examples and translations

## Explicit non-goals for `1.3.x`

- Storing passwords, private keys, payment-card data, or other highly sensitive secrets
- Advertising, selling user data, or personalized advertising
- Automatic reading of page contents or browsing history
- Persistent access to every website
- Paid subscriptions or in-product payments

## Influence the roadmap

Open a [feature request](https://github.com/abhay-yemekar/ydirect/issues/new?template=feature_request.yml) with the problem, who experiences it, and what success would look like. Do not submit vulnerabilities in public issues; follow [SECURITY.md](SECURITY.md).
