# Security policy

## Reporting a vulnerability

Please report suspected yDirect vulnerabilities privately to [support@ydirect.tech](mailto:support@ydirect.tech?subject=yDirect%20Security%20Report).

Do not create a public GitHub issue for security-sensitive findings.

Include, when safe and relevant:

- affected yDirect version and surface;
- Chrome version and operating system;
- a clear description of the impact;
- minimal reproduction steps using synthetic data;
- screenshots or recordings with sensitive details removed;
- any conditions required to reproduce the behavior.

Do not include passwords, access tokens, session cookies, private keys, real user snippets, real customer information, or destructive proof-of-concept payloads.

## Scope

Security reports may concern:

- the published yDirect Chrome extension;
- official yDirect account, support, privacy, terms, and action pages;
- authenticated backup, workspace, sharing, feedback, and account-operation behavior;
- unauthorized data access, privilege errors, unsafe import/export handling, or account-boundary failures.

This public repository contains documentation and media rather than production source. Documentation typos and broken links can use ordinary GitHub Issues unless they expose sensitive information.

## Responsible testing

- Test only accounts and data you own or are explicitly authorized to use.
- Use synthetic data.
- Avoid privacy violations, service disruption, spam, social engineering, denial of service, and destructive actions.
- Stop when a test could access another person's data.
- Give the owner a reasonable opportunity to investigate before public disclosure.

## Response process

Valid reports are triaged by impact, reproducibility, affected users, and exploitability. The reporter may be asked for clarification or a safe reproduction. Remediation and disclosure timing depend on technical risk, user protection, platform review, and required external coordination.

No bounty or payment program is currently promised. Please confirm scope before investing substantial time in testing.
