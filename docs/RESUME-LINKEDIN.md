## Portfolio case-study outline

1. **Problem:** repeated text was scattered and costly to retrieve.
2. **Research:** mapped workflows across support, sales, recruiting, development, and personal productivity.
3. **Product decision:** focused on copy-ready snippets rather than automatic page capture.
4. **Interaction model:** attached right-edge workspace opened only on demand.
5. **Data model:** local-first working state, explicit exports, optional recovery, scoped collaboration.
6. **Trust model:** user-triggered page access, backend authorization, verified accounts, transparent permissions.
7. **Delivery:** Manifest V3 client, Firebase stack, transactional email, tests, hosting, legal/support surfaces, store submission.
8. **Trade-offs:** private source with public product documentation; two-point backup rather than archival storage; copy-first rather than automatic insertion.
9. **Outcome:** version `1.3.1` submitted to the Chrome Web Store with a public, resume-ready product record.
10. **Next:** onboarding, backup confidence, keyboard discovery, accessibility review, and deeper collaboration controls.

## Interview talking points

### Why not publish the source?

The implementation and operational controls are product IP, but privacy, architecture, permissions, ownership, scope, roadmap, and user support still benefit from public accountability. The showcase repo separates portfolio transparency from source distribution.

### What was the hardest product trade-off?

Balancing quick in-page access with permission minimization. yDirect uses a user-triggered `activeTab` and `scripting` model so the attached workspace can appear where it is useful without requesting persistent access to every site.

### What demonstrates Product Owner work?

Defining the single purpose, prioritizing a release scope, modeling roles and permissions, establishing non-goals, translating privacy constraints into behavior, maintaining release gates, and presenting the product for users, reviewers, and stakeholders—not only implementing features.

### What would you measure after launch?

- successful first folder and first copy completion;
- time from open to copy;
- search success and empty-result rate;
- backup enablement and tested-restore completion;
- error-free sessions and support issue themes;
- sharing invitation acceptance and access-removal reliability;
- retention, uninstall reasons, and qualitative workflow outcomes.

Do not invent download counts, time saved, retention, ratings, stars, or performance improvements until measured with a documented method.
